# Ready-circle app icon badges

0.5.3 (50) counts distinct circles in which the account has an unsubmitted, currently permitted entry. Daily plus end-of-day in one circle counts once. Completing only one still counts if the other remains ready. Ordinary peer posts/responses do not increment this badge; alert preferences do not change readiness. Existing server entry rules determine open, late, first-day/welcome and evening cutoffs. Scheduled prompts, removed memberships, completed prompts and suspended/deleting accounts do not add readiness.

The authenticated `my_ready_blessing_circle_ids()` RPC has no caller-supplied account or clock parameters. It returns ready **and unanswered** circle IDs using server time and a private helper around the existing entry predicate. The app uses these IDs for circle-dropdown dots and their count for its icon badge. Migration `202611030002` adds this read; the existing integer RPC and server delivery continue using the same predicate via the shared IDs helper. Older clients remain compatible. Swift local-demo IDs/counting are separately deterministic. The app refreshes on its existing metadata/mutation paths and once per minute while active, coalesces queued refreshes, and fences old account/read completions. Failed queries preserve the last known count and IDs. Menu opening also requests a fresh readiness read; the dropdown lists joined circles only, with join/create available under Manage circles or the Circle tab. Sign-out revokes the current account's installation registrations before ending the session, unregisters remote notifications locally and clears the badge. Accepted account deletion also clears it. An unsuccessful sign-out attempts to restore device registration.

Migration `202611020008` adds private, RLS-protected per-device delivery state and service-only claim/complete RPCs. The existing minute dispatcher reconciles absolute counts, including changes caused solely by elapsed time. It claims only changed counts or changed APNs token hashes, with a two-minute lease, skipped locked rows, a bounded batch, stale-ack fencing and a one-minute retry delay after a failure. APNs acceptance is acknowledged persistently; a failed acknowledgement is retried after the lease. Invalid-token cleanup compares the claimed token so it cannot erase a replacement.

Badge delivery uses a separate quiet APNs envelope containing only `aps.badge`. It includes no alert, sound, name, circle identity, post content, media, or deep link. Regular alerts never carry an older badge count. A shared collapse ID replaces pending badge updates, a 15-second request bound limits ambiguous work, and expiration zero avoids queuing old counts for a disconnected device. [Apple documents the badge value and zero clearing](https://developer.apple.com/library/archive/documentation/NetworkingInternet/Conceptual/RemoteNotificationsPG/PayloadKeyReference.html). Absolute counts make repeated delivery idempotent; APNs ordering/delivery is still best effort. Offline devices can retain an old badge until another update or foreground refresh. Already-issued pushes cannot be recalled.

The existing notification authorization includes Badges; users can disable it in iOS Settings. This adds no advertising tracking or content collection. Operational state is private and cascades away with its device registration; logs contain aggregate outcome counts only. It does not enable recording cleanup or alter notification text/privacy.

Verification: the full migration-chain harness includes rollback-only readiness/lease/authorization/token/revocation fixtures, without APNs calls. The pure payload/delivery contract tests isolate send and acknowledgement failures. The live deployment uses exact predecessor/source hashes and a bounded hosted rollback trial; read-only acknowledgement counts demonstrate APNs acceptance, not physical icon display. Before public release, verify on a physical installation: two ready circles → 2; daily and evening in one → 1; one remaining opportunity → 1; completed circles → 0; foreground/closed app, permission off/on, another device posting, expiry, sign-out and account deletion.
